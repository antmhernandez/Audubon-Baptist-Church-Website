# Project Vision

## Purpose

The Audubon Baptist Church web platform should help three groups well:

1. **Guests and prospective attendees** should quickly understand who the church is, what it believes, when it gathers, where to go, and what to expect.
2. **Church members** should have a calm, trustworthy place for sermons, events, prayer, signups, ministry information, and discussion.
3. **Church leaders and administrators** should be able to maintain content without editing code.

The platform should feel like a useful extension of church life rather than a complicated technology project.

## Product principles

### Christ and church life before technology

Technology should make ordinary church communication easier. It should not become an attraction in itself.

### Comfortable for young and old

Use:
- generous type sizes;
- strong contrast;
- large touch targets;
- plain language;
- predictable navigation;
- minimal required steps;
- mobile layouts that do not assume technical expertise.

### Public by intention, private by intention

Every data type should have an explicit audience. The system must never assume that a prayer request, ministry post, RSVP, member name, or leadership note is public merely because it exists in the database.

### One platform, gradual complexity

Begin with:
- public site;
- sermons;
- events;
- role-aware member preview;
- administration model.

Then add secure authentication, database-backed content, prayer workflows, real RSVPs, groups, media processing, and giving integrations in measured phases.

### Financial responsibility

Prefer:
- open-source application code;
- GitHub as source of truth;
- free or low-cost hosting at early scale;
- replaceable service providers;
- no unnecessary native app until usage justifies it;
- video storage/delivery separated from the core application.

## Success criteria

A successful first production release should allow a first-time visitor to answer within a minute:

- Who is Audubon Baptist Church?
- What does the church believe?
- When does it meet?
- Where is it?
- What should I expect?
- How can I contact someone?
- Can I watch a sermon?

A member should be able to answer:

- What is happening this week?
- What have I signed up for?
- Where can I find the prayer list?
- How can I volunteer?
- Where can I find the latest sermon or church announcement?

An administrator should be able to:

- edit homepage information;
- publish a sermon;
- add or edit an event;
- manage visibility;
- moderate submitted content;
- do so without touching GitHub or application code.
